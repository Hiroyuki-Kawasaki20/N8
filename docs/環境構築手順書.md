# N8かんばんセット 開発環境構築

このプロジェクトは開発中です。N8の3工程＋リリーフは未実装のため業務投入せず、exeも使用・配布しないでください。初期確認は本番データやSPO監視先ではなく、専用の試験フォルダで行います。

## Python環境

本人のWindowsアカウントで、組織の承認済み手順に従いcondaとPython 3.11の本人専用 `N8_new` 環境を用意します。既存のCH用 `DIG_new` は変更しません。作成権限がない場合は担当者へ依頼してください。

以下はAnaconda Prompt用の作成例です。既に `N8_new` 環境がある場合は削除・再作成せず、`conda env list` 等で実際の場所を確認してください。起動時には本人ホーム配下の `N8_new` フォルダを指定します。

```bat
conda create --prefix "%USERPROFILE%\.conda\envs\N8_new" python=3.11
conda activate "%USERPROFILE%\.conda\envs\N8_new"
```

次にN8のソースを配置したフォルダへ移動し、既存の [requirements.txt](../requirements.txt) を確認してからライブラリを導入します。次の個別配置のパスは例です。本人の実際の配置先に読み替えてください。共通配置の場合も、実際の共通配置先へ移動します。`requirements.txt` が見つからなければ導入を進めず、配置先を確認してください。

```bat
cd /d "%USERPROFILE%\DIG_Project\N8かんばんセット"
dir requirements.txt
python -m pip install -r requirements.txt
python -m pip check
```

プロキシ・取得先・証明書は社内指定の方法を使用し、認証情報を文書に記載しないでください。証明書検証やPowerShellの制限を無条件に解除しないでください。

この作業自体では環境作成・パッケージ追加・更新を行っていません。`N8_new` が本人のホーム配下にあり、`python.exe` と `conda-meta` を含むことを確認します。本人のユーザー環境変数 `N8_KANBAN_ENV_PREFIX` に、作成した環境フォルダの絶対パスを設定してください。末尾に `python.exe` を付けません。既存環境の場所が次の例と異なる場合は、実際の場所に読み替えてください。

```bat
set "N8_KANBAN_ENV_PREFIX=%USERPROFILE%\.conda\envs\N8_new"
setx N8_KANBAN_ENV_PREFIX "%USERPROFILE%\.conda\envs\N8_new"
```

`setx` の反映には新しい端末・起動プロセスが必要です。`CH_KANBAN_ENV_PREFIX` は使用・変更しません。condaは本人用または承認済みの全ユーザー用を自動検出します。自動検出できない場合、本人の `CONDA_EXE` に実際の承認済み `conda.exe` の絶対パスを指定できます。既存値の変更が必要な場合は他の用途への影響を確認してください。baseやシステムPythonへの代用はしません。


GUI、本番入力、SPO出力、設定の読込・作成・移行は行いません。conda、Python、ライブラリと各保存先を表示し、N8領域に起動ログを記録します。PowerShellの実行が禁止されている場合は管理者へ相談し、実行ポリシーを独断で変更しないでください。

## 初回設定と保存先

開発時に通常起動を確認する場合は、[run_n8_kanban.bat](../run_n8_kanban.bat) から起動し、N8専用の試験入力先・出力先を選択します。次回は保存済みの有効なパスを再利用します。CHや本番SPOのフォルダは選択しないでください。

保存基準は `%LOCALAPPDATA%\N8Kanban` です。`LOCALAPPDATA` が未設定・空の場合は本人ホームの `AppData\Local\N8Kanban` を使用します。必要なフォルダは保存時に作成します。

| 対象 | 基準配下 |
|---|---|
| 設定 | `ch_kanban_settings.json`（既存形式・キーを維持） |
| 終了時刻履歴 | `lane_end_times_history.json` |
| ローカル出力 | `output/` |
| アプリ・起動ログ | `output/logs/` |
| 一時出力 | `output/_staging/` |
| 既定アーカイブ | `output/_export_archive/` |

CHの設定・履歴やアプリ隣の旧設定は自動読込・移行しません。`archive_dir` や `master_path` の明示指定は従来どおり有効です。明示的にCH側のパスを指定しないでください。設定の既存キーは保持され、書込み失敗は通知されます。
